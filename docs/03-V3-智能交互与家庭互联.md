# 03 - V3 智能交互与家庭互联

> **本文档定位**：V2 稳定运行2个月后的下一阶段规划。
>
> **核心目标**：从"单设备提醒"升级到"全屋互联"，让看护人在任何房间都能响应奶奶的需求。

---

## 3.1 版本概述

| 项目 | 内容 |
| :--- | :--- |
| **前置条件** | V2 已稳定运行 ≥ 2个月，防坠床误报率 < 5%，手环读取成功率 ≥ 90% |
| **预计工期** | 约1周（协议对接+UI调整+硬件部署） |
| **预估成本** | ~100元（从音箱×2） |
| **核心主题** | 家庭互联：环境感知 + 全屋广播 + 视频通话 + 健康周报 |

---

## 3.2 功能模块

### 3.2.1 环境感知联动

| 属性 | 规格 |
| :--- | :--- |
| **功能描述** | 增加温湿度传感器。点击"热/冷"时，屏幕短暂显示当前室温，播报"室温26度，需要开空调吗？" |
| **硬件新增** | DHT22温湿度传感器（GPIO单总线） |
| **显示位置** | 二级菜单"热/冷"按钮点击后，闪屏层额外显示温度和湿度 |
| **语音逻辑** | 先播奶奶原话（泰顺话"热/冷"），再追加播报当前室温（TTS合成或预录音） |
| **联动建议** | 若温度>28℃，建议"开空调"；若<18℃，建议"加被子" |

**硬件接线：**

```
DHT22 (DATA) → GPIO4 (BCM)
DHT22 (VCC)  → 3.3V
DHT22 (GND)  → GND
```

### 3.2.2 全屋语音广播

| 属性 | 规格 |
| :--- | :--- |
| **功能描述** | 在客厅、厨房放置廉价从音箱。奶奶按下任意按钮，全屋同步播放方言语音 |
| **硬件新增** | 有线/蓝牙从音箱 × 2（或 WiFi 音频接收器，如小米小爱音箱Play） |
| **广播内容** | 按钮对应的方言音频 + 位置提示（如"儿子快来客厅！"） |
| **广播范围** | 主卧（主设备）、客厅、厨房 |
| **音量策略** | 从音箱音量为主设备的 70%，避免刺耳 |
| **延迟要求** | 主设备出声 → 从音箱出声 ≤ 500ms |

**技术方案对比：**

| 方案 | 优点 | 缺点 | 推荐度 |
| :--- | :--- | :--- | :--- |
| 蓝牙从音箱 | 简单、低延迟 | 距离受限、干扰多 | ★★★ |
| WiFi音频同步 | 覆盖广、稳定 | 延迟稍高（~300ms） | ★★★★ |
| 有线音箱并联 | 零延迟、最稳定 | 布线麻烦 | ★★★★★ |

> **推荐**：若三兄弟家装修允许，优先有线方案；否则用 WiFi 方案（如 Snapcast）。

### 3.2.3 一键视频通话

| 属性 | 规格 |
| :--- | :--- |
| **功能描述** | 屏幕增加带亲属头像的按钮，点击后自动拨通微信/企业微信视频通话 |
| **硬件新增** | 旧手机 + 支架（已有，利用闲置设备） |
| **实现方式** | 树莓派通过 ADB 控制旧手机，自动打开微信并拨打指定联系人 |
| **联系人配置** | config.json 中预配置亲属微信昵称/企业微信手机号 |
| **按钮布局** | 在主菜单增加第三行："📹 视频"按钮，点击进入亲属选择页 |
| ** fallback** | 若微信无法自动拨通，改为拨打普通电话（ADB 模拟拨号） |

**ADB 控制示例：**

```bash
# 唤醒手机
adb shell input keyevent KEYCODE_WAKEUP
# 打开微信
adb shell am start com.tencent.mm/.ui.LauncherUI
# 模拟点击搜索、输入昵称、点击视频通话
# （具体坐标需根据手机分辨率适配）
```

> ⚠️ **注意**：微信自动视频通话可能因微信版本更新而失效，需预留手动备用方案。

### 3.2.4 健康周报导出

| 属性 | 规格 |
| :--- | :--- |
| **功能描述** | 自动整合按键频次、手环心率均值，生成一页纸的PDF可视化报告 |
| **生成周期** | 每周日早6:00自动生成 |
| **推送方式** | 企业微信群文件推送（或保存到U盘根目录） |
| **报告内容** | 按键热力图、体征趋势折线图、异常事件列表、医生问诊建议栏 |
| **技术实现** | Python + matplotlib 生成图表 + reportlab 生成PDF |
| **用途** | 家属带去医院复查时，直接出示给医生 |

**报告模板示意：**

```
┌──────────────────────────────────────────┐
│  奶奶健康周报（2026.09.01 - 2026.09.07）   │
├──────────────────────────────────────────┤
│  [按键频次柱状图]    [心率趋势折线图]      │
├──────────────────────────────────────────┤
│  异常事件：                              │
│  - 09/03 凌晨 02:10 疼痛按钮触发           │
│  - 09/05 14:30 紧急按钮触发               │
├──────────────────────────────────────────┤
│  医生问诊记录栏（留白供手写）               │
└──────────────────────────────────────────┘
```

## 3.3 V3 界面变更

V3 在主菜单增加"📹 视频"入口，变为 **3个按钮**（或保持2个主按钮，将视频作为二级菜单）。

**推荐方案：保持2个主按钮不变，在"唠家常"二级菜单增加"📹 想见谁"按钮。**

理由：避免主菜单变复杂，奶奶的主要需求仍是"表达"和"求救"。

---

## 3.4 V3 非功能性需求

| 指标 | 要求 | 验收标准 |
| :--- | :--- | :--- |
| 温湿度读取延迟 | 点击"热/冷"→显示温度 | ≤ 1秒 |
| 全屋广播同步 | 主设备出声→从音箱出声 | ≤ 500ms |
| 视频通话启动 | 点击→拨通 | ≤ 15秒（含微信启动） |
| 周报生成 | 周日6:00→推送完成 | ≤ 5分钟 |

---

## 3.5 V3 → V4 的衔接条件

V3 可进入 V4 的前提：
1. 全屋广播无啸叫、无回声，体验良好
2. 视频通话成功率 ≥ 80%
3. 健康周报被家属和医生认可，确实提升了问诊效率
