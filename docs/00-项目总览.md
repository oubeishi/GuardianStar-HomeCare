# 00 - 项目总览

> **本文档定位**：项目顶层说明，供首次接触本项目的评审人、开发者快速建立全局认知。

---

## 1. 为什么做这个项目

### 1.1 痛点背景

奶奶（目标用户）当前面临的核心困境：

| 痛点 | 具体表现 | 后果 |
| :--- | :--- | :--- |
| **表达缺失** | 左侧偏瘫软瘫期，右手无力抬举，无法用手势或书写表达需求 | 想喝水、想翻身、想见儿女，只能干瞪眼或含糊哼唧 |
| **求救无门** | 夜间独自卧床，若出现疼痛、呼吸困难，无法有效呼叫 | 延误救治窗口，次生风险极高 |
| **信息断裂** | 三兄弟轮换照顾，每人只知道自己值班时的情况 | 无法形成连续的健康档案，医生问诊缺乏依据 |

### 1.2 现有方案为何不够

- **华为手环10**：只能监测血氧/心率，无法让奶奶"说出"需求。
- **传统呼叫铃**：只有一个按键，无法区分"想喝水"和"疼"。
- **智能音箱**：需要语音唤醒+普通话指令，对文盲+方言老人完全不可用。

## 2. 目标用户画像

| 维度 | 描述 |
| :--- | :--- |
| **年龄/性别** | 80+ 岁，女性 |
| **身体状况** | 左侧偏瘫（软瘫期），右手肌力≈0级，无法抬举 |
| **认知能力** | 清醒，能辨认儿女，有明确表达意愿 |
| **教育背景** | 文盲，完全不识字 |
| **视力状况** | 老花眼（需大图标、高对比度） |
| **语言** | 只会泰顺蛮讲话，听不懂普通话 |
| **使用场景** | 90% 时间卧床，10% 时间轮椅活动 |
| **技术接受度** | 零，界面必须直观到"看见就知道按" |

> **设计铁律**：任何需要"学习"的操作，对这位用户来说都是不可用的。

## 3. 技术底座

| 层级 | 选型 | 理由 |
| :--- | :--- | :--- |
| **主控** | 树莓派 5B（4GB RAM） | 已有设备；GPIO丰富；社区生态成熟 |
| **显示** | 10寸 HDMI 触控屏（1920×1280） | 已有设备；大屏适合老花眼；分辨率充足 |
| **音频** | 3.5mm USB供电小音箱 | 强制走3.5mm口，避免HDMI音频冲突 |
| **系统** | Raspberry Pi OS（64位） | 稳定、易维护、Python原生支持 |
| **GUI框架** | Tkinter | Python内置、无需额外依赖、全屏控制简单 |
| **数据存储** | 本地 JSON + 文本日志 | 零云端依赖、断网可用、隐私安全 |
| **通知通道** | 企业微信群机器人 | 家属用微信即可接收群消息，零新增APP成本 |

## 4. 核心设计原则

```
┌─────────────────────────────────────────┐
│  零文字  →  纯色块 + 超大 Emoji          │
│  零学习  →  点一下就有反馈               │
│  零歧义  →  按什么就说什么               │
│  零遗忘  →  每按一次都自动记录           │
│  零遗漏  →  紧急情况多渠道并行告警        │
└─────────────────────────────────────────┘
```

        ┌──────────┐           ┌──────────┐           ┌──────────┐           ┌──────────┐
        │ 12词表达  │   ───▶   │ 防坠床   │   ───▶   │ 环境感知  │   ───▶   │ 非接触交互│

## 6. 项目风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 奶奶右手进一步无力 | 无法触屏 | V4 规划了手腕倾斜开关（非接触式） |
| 三兄弟家路由器更换/密码变更 | 设备失联 | V4 规划了自适应 WiFi 配网 |
| 泰顺话音频录制质量差 | 奶奶听不懂 | 提前让家人试听确认，预留重录通道 |
| 夜间误触紧急按钮 | 家属疲劳 | 警报窗需点击关闭，日志可追溯 |
| 设备被盗/损坏 | 服务中断 | 成本低（≈200元），可快速更换整机 |
