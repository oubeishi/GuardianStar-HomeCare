## 5.2 风险与坦诚说明

### 5.2.1 V1 局限性（必须向评审人坦白）

- **无AI能力**：不包含跌倒检测、人脸识别、语音识别（依赖华为手环做基础生命告警）。
- **单向沟通**：只能帮奶奶"说出"话，不能理解她说出的模糊声音（仍依赖人工响应）。
- **词库固定**：12个短语在一段时间内是固定的，如需修改需手动替换音频文件并重启程序。
- **无远程管理**：不能通过手机远程查看状态或修改配置，必须现场操作。

### 5.2.2 最坏情况预案

| 最坏情况 | 影响 | 预案 |
| :--- | :--- | :--- |
| 设备彻底损坏/被盗 | 服务中断 | 成本低（≈200元），可快速更换整机；配置文件和音频有备份 |
| 奶奶完全丧失行动能力 | 无法触屏 | V4 规划了手腕倾斜开关，提前准备 |
| 三兄弟分歧，项目停滞 | 无人维护 | 代码和文档全部开源备份，任何有Python基础的人可接手 |
| 企业微信机器人被封 | 通知中断 | 预留 SMTP 邮件通知作为 fallback |

## 5.3 评审需确认的3个关键点

### 🔑 关键点 1：V1 立即启动

> **问题**：是否同意采购剩余硬件（音箱、支架、按钮），并在本周内完成部署？

| 方案 | 成本 | 时间 |
| :--- | :--- | :--- |
| A. 立即启动 | ~¥230 | 3天内到货+1天部署 |
| B. 暂缓观察 | ¥0 | 继续现状，风险不变 |
| C. 精简版 | ~¥100（仅音箱+按钮，无支架） | 2天内 |

**建议选 A 或 C**：硬件成本极低，即使最终不适用，损失也可接受。

### 🔑 关键点 2：数据隐私

> **问题**：企业微信机器人通知涉及奶奶隐私数据（疼痛时间、日志），是否所有兄弟都能接受群内推送？（家属在普通微信中即可接收，无需安装企业微信App）

| 方案 | 说明 |
| :--- | :--- |
| A. 全员可见 | 所有兄弟都在企业微信群，数据透明（普通微信即可接收） |
| B. 仅指定人 | 只推送给主要看护人，其他人看不到 |
| C. 匿名推送 | 推送中隐去具体 button 名称，只说"有需求" |

**建议选 A**：家庭内部照顾，信息透明有助于协同；若某兄弟介意，可单独沟通。

### 🔑 关键点 3：V2 优先级

> **问题**：如果 V1 运行良好，是否优先推进"床垫压力防坠床"还是"蓝牙手环接入"？

| 方案 | 解决的核心痛点 | 推荐度 |
| :--- | :--- | :--- |
| A. 优先防坠床 | 夜间坠床后果最严重，可能导致骨折、颅内出血 | ★★★★★ |
| B. 优先手环 | 沉默性缺氧更隐蔽，但手环已有独立告警 | ★★★★ |
| C. 并行推进 | 两者同时做，但工期翻倍 | ★★★ |

**建议选 A**：防坠床是夜间最高风险，且传感器方案简单、成本低、见效快。手环数据作为辅助，优先级略低。

## 5.4 一句话总结

> **"我们花的每一分钱、每一行代码，都对应着一个具体的风险或痛点。V1 用不到 300 元解决奶奶'说不出话'和'求救无门'的刚需，这是投入产出比最高的第一步。"**
